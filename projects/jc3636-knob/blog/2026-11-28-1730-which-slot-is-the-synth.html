Which slot is the synth? The function names are lying

2026-11-28 17:30 (+0800) · part 34 of 57 labmidibleapidocs

The knob talks to two Bluetooth devices at once: whichever connects first gets slot 0. The keyboard might win the race. The synth might. The skill says so in bold: do not assume slot 0 is the keyboard.

Then the module gives you these:

const char *ble_midi_smk_label(void);  // slot 0's device name once connected, else "BT 1"
const char *ble_midi_fm1_label(void);  // slot 1's device name once connected, else "BT 2"

smk_label() is whatever is in slot 0. If the FM-1 connected first, smk_label() returns "FM-1_BLE". The names describe the usual case and the comments describe the truth.

What the apps did

Credit where due: five of the seven piano apps look up the keyboard by name, like the skill says:

const char *lbl = s == 0 ? ble_midi_smk_label() : ble_midi_fm1_label();
if (strstr(lbl, "SMK") || strstr(lbl, "Pro")) return s;

That line is correct, and it's correct because the function names are wrong. Read it cold and it looks like a bug.

Octave Jumper sidesteps it by sending to both slots with ble_midi_send(), so the keyboard gets the synth's notes too. Key Speed doesn't do the lookup at all. Its header prints slot 0's state as "KEYBOARD" and slot 1's as "FM-1". On a day the synth wakes up first, it will tell me the keyboard is the synth.

What nobody tested

Every one of the 19 BLE feature scripts connects slot 0 first (Key Speed's four never connect slot 1 at all). Not one connects the FM-1 first, which is the case all that care exists for. The simulator can do it (midi_conn 0 2 fm1). Nobody asked it to.

The fix: ble_midi_slot_label(int slot) in modules/ble_midi/, keep the old two as aliases, and one feature line per piano app with the synth in slot 0. Small change. Saves a whole class of "it worked yesterday".
