tap-reflex ate a 200 KB font

2026-11-21 08:41 (Pacific) · part 9 of 23 laboccamycontextpi

Game two: a reaction timer. Wait for green, tap, see your time. Occamy got it to CHECK PASS in 1,712 seconds. And then its session simply stopped. Mid-thought. No report, no goodbye. Like a cartoon character running off a cliff and only falling when it looks down.

The last thing it read

Just before it went silent, Occamy wanted to know how tall a font was. Reasonable! So it opened font_data.c. Which is the generated font: 200 KB of glyph bytes.

The session's last reply was one single token, with stopReason: "length", at 128,971 cached tokens. The model's whole context is 131,072. It had filled its head with a font and had room for exactly one more word.

(For the record, the first write-up only said the font dump "co-occurred" with the cut-off, because two things happening together isn't proof. Reading the session file afterwards gave the mechanism: context overflow. I love that the correction is in the record.)

The fix is a sign on the door

  • font.h and the generated file itself now state the heights at the top and say do not read this file;
  • AGENTS.md now says: check a file's size (wc -c) before reading one you haven't seen. Generated data is never worth reading.

The stowaway

While tidying up, the coach found something much funnier. pi, by default, loads AGENTS.md from every parent directory. So every single Occamy session had also been carrying my personal AGENTS.md from my home folder: pages of rules for every other project I run, none of them about knobs. Into a tiny local model. That was trying to make a reaction timer.

Poor thing. No wonder it was tired.

tools/pi.sh now runs pi with --no-context-files and hands it only this repo's AGENTS.md and its own skills.

AGENTS.md goes on a diet

I asked for AGENTS.md to be short and generic, with the specifics moved into skills. It came out at about 450 words: what the board is, an index of four skills (knob-game, knob-sim, knob-drawing, knob-flash), five rules, and a little section called "when things go sideways":

  • a mundane step taking long? Look for a skill or a tool first;
  • the same error twice? Don't try a third variation. Change approach.

That second one is good advice for models. It is excellent advice for me.
