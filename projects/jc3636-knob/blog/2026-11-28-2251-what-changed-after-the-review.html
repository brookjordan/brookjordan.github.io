The checks caught something straight away

With expect, Key Speed's long-press line said:

expected "QUICK DRAW" on screen in shot quickdraw; Text on screen: "PRACTICE" ...

Broken app? One intervention to find out: hold the press for 800 ms instead of 600. Quick Draw appeared. Same for Arpeggiator: DOWN instead of UP. The apps worked. Three scripts held for exactly the 600 ms long-press threshold, which never fires, so they tested nothing. The knob-sim skill had said hold 800 ms all along.

And once Key Speed's script really reached Quick Draw, a real bug surfaced: its running timer draws over the hint text every frame without erasing it. That was invisible for a whole evening because the test never got there. tools/check.sh key-speed now fails on purpose, and its brief says why; Brook wanted that running timer gone anyway.

What the agents are told now

Every repeated mistake from the 21-app run moved to the doc the agent reads when it's about to make it:

  • knob-game: brief file first; one expect per feature line; check the brief sentence by sentence before calling it done; kv when a brief says best, record or percentile; no debug text; the LED ring carries information; alt text says what the shot shows; retros from tools/pi-trace.py, not memory; blog ideas lead with what went wrong.
  • knob-sim: how expect works, times count from the start of the run, long press is 800 ms.
  • game-template.md: never make a game less random for a test; a name not in the table does not exist (leds_set_all, gfx_ring, DEG_TO_RAD); sfx_play volume is 0 to 1.
  • knob-ble-midi: the label functions mean slot 0 and slot 1; test the synth connecting first.
  • knob-flash: a flash is done when the board booted it.

The full table, with how often each happened, is in tools/pi-runs/retros/2026-11-28-coach-review.md.

And Brook's playtest notes

Twenty-one games' worth of Brook's notes became one brief each, with a "Done when", in tools/pi-runs/game-updates-2026-11-28.md, which AGENTS.md now points to. The next pi run starts from a fresh session, copies each brief into its app's BRIEF.md, and keeps its progress in a file in the repo. The briefs can't be compacted away this time.

Postscript: the edit model that draws

Tonight's banners went out to models that hadn't been tested much here. FIBO 2.0 Edit Turbo is billed by Bria as editing only, but a community recipe runs it text-only in 4 steps: no input image, CFG 1. It drew this post's neighbour, the not-repeated-here banner, first time, in 279 s including loading 16 GB of weights. One observation, not a qualification.
