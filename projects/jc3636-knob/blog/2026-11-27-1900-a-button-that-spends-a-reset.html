A button that spends a reset

2026-11-27 19:00 (+0800) · part 23 of 26 usage panelresetsopenaiclaudez.airate limits

OpenAI gave everyone a free "banked reset" this week, a saved refill of your Codex limits you spend whenever you like. My ChatGPT pane was showing two maxed bars and I had four of them sitting unused. So, obviously, the knob needed a big friendly button to spend one.

The button, and the dial that guards it

Here is the dance. The pane shows use reset (4). Tap it and a confirm screen appears: a dial of twelve dots, a pointer you move with the knob, and an amber ring at a random spot. Reset stays greyed out until the pointer sits on the ring. Turn past it and it greys out again. Cancel, or thirty seconds of nothing, goes back to the panes.

It's a combination lock with one number. For a free refill. Proportionate? No. Delightful? Yes. (Later that evening another session tightened it so the ring always sits at least four detents away, so a nudge can't do it by accident.)

The knob doesn't talk to OpenAI. It asks the agent on the laptop, which makes the same call Codex CLI's own /usage → Redeem reset makes. I didn't guess that call: the Codex CLI is open source, so the agent copies the request straight from it, request id and all. That id is an idempotency key, so one confirmation can spend at most one reset, however many times the request is retried.

The first real press, from the log:
19:00:53 panel sends the reset
19:00:57 ChatGPT answers reset
19:00:58 panel shows DONE
after 4 resets → 3; both bars from maxed → 6% and 1%

Five seconds from tap to refilled. Chef's kiss.

Claude had one too, in a binary

The guides say Claude's resets are spent on claude.ai, not in Claude Code. But the Claude Code binary on my laptop has to name every endpoint it calls, and strings on it turned up reset_rate_limits, with two programmes behind it: banked grants, and a weekly one that only appears when you've hit your limit.

The status comes back in the same usage reply the agent already reads, but only if you ask in the right voice. With the agent's old User-Agent, both programmes said ineligible_reason: "surface". Ask as Claude Code (claude-cli/2.1.332 (external, cli)) and there it was: one full limit reset, usable now, expiring 10 December. Same account, same token, different hat.

Z.AI's was in another country's website

Z.AI calls them Quota Reset Cards. Its international console has no code for them at all, which was briefly very confusing. Then I looked at the Chinese sister site, bigmodel.cn, which runs the same backend. Its console bundle has a ResetQuotaCard component and two endpoints, one to list your cards and one to use one. The international API answers both with the key the agent already holds.

Three cards. In my account. Unspent. The first one expires on 22 December.

All three panes now grow the same button whenever their provider has a reset, and lose it when they don't. The firmware didn't change for Claude or Z.AI at all: any pane with an action gets the button. I love a generic renderer.

And then I rate-limited myself

The Anthropic pane started saying rate limited, which also hid its shiny new button. Rude.

The usage endpoint allows about 30 reads an hour per account, shared with every Claude Code session on that login (an account-switching tool, claude-swap, measured it). A 429 then locks you out for whatever retry-after says, and retrying inside the lock makes it longer.

The agent was polling every 120 seconds. That's 30 an hour. The panel was spending the entire budget on its own, before Claude Code got a look in. And at start-up it sent two reads in the same second. No-one else was hammering my rate limit. It was me, from inside the house.

The fix: read every five minutes; after a 429 send nothing until it clears, with the wait written to disk so a restart can't cheat; never have two reads in flight. When the server says retry-after: 0, which it did, wait fifteen minutes, as people who'd been burned before recommend (the coach briefly cut it to five, then found that advice and put it back). The pane now says next read 22:06 instead of rate limited, keeps its last figures, and keeps the button.

The coach also shipped a bug here: pressed during a lockout, straight after an agent restart, the Claude button said no reset left, because the grant to fall back on lived only in memory and the restart had wiped it. Another session reworked it so a press during a lockout now says when to try again. Honesty, delivered late, but delivered.
