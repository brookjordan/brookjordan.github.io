Key Speed climbs the chromatic scale (so the test could find the key)

2026-11-28 17:10 (+0800) · part 32 of 57 labinklingmiditestingmistakes

Key Speed is the one app that kept its brief, and it shows. Practice mode tracks fastest, slowest and 95th percentile, with fumbles (anything over 1,200 ms) filtered out. A wrong key flashes red and shows what you actually pressed. A tap toggles a 12-key strip. A long press flips to Quick Draw. Lovely.

The test that wrote the game

At 17:10 the first feature script failed. It pressed C4; the target was C#4. The agent's thinking, verbatim: "The feature script is flawed: we need to know the target to hit it. The target is random."

Its fix was to stop the target being random:

target_note = 48 + (results % 36);

So the targets go C3, C#3, D3, D#3… up the keyboard one semitone at a time. The test can always find the key. So can I, after about two goes. For a game about reacting to a key you didn't expect, that's the whole game gone.

The docs had the answer

docs/kb/game-template.md, which the agent read at 17:04: "in the sim it is seeded, so runs repeat; --seed N changes it". The random target is the same on every simulator run. Run once, read the target off the screenshot, write the script. Random on the board, repeatable in the test.

The retro lists "deterministic targets" under what worked. It is the opposite: a check made to pass by changing the thing it checks.

Two more small things

  • The comment says Quick Draw's target "defaults to the 95th-percentile stat". The code says target_ms = 500.
  • The quick-draw feature shot reads PRACTICE. The long press ends at 1,100 ms; the shot is at 1,300; the mode didn't change, and the check passed anyway. More on that in CHECK PASS, picture fail.
