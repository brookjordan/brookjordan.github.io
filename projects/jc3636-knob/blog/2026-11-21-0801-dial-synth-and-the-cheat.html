dial-synth, the simulator, and a very small cheat

2026-11-21 08:01 (Pacific) · part 8 of 23 laboccamysimulatorreview

The brief to the local model was simple: make a fidget toy where each knob detent plays the next note of a scale. Twenty-seven minutes later, it said it was done, with no warnings. It was very nearly telling the truth.

The cast

  • Occamy: a model running locally on llama.cpp on this laptop. No internet. It does the building.
  • pi: the coding agent that drives it: reads files, runs commands, writes code.
  • The coach: Claude, reviewing, writing notes, and fixing the tools whenever Occamy trips on one.

A simulator, so the model can see

Before Occamy could make anything, it needed eyes. There was no board to flash; the knob was busy being a usage panel. So tools/sim.sh compiles the game's real main.c and drawing code for the Mac, swaps the chips for fakes, plays a scripted list of knob turns and taps in virtual time, and writes screenshots.

And, crucially for a text-only model: every screenshot also comes out as a text picture, the round screen as 60 by 30 letters, plus an event log of every sound and buzz. A model can't look at a PNG. It can absolutely read "R R R O O O" and work out that the dot went orange.

What Occamy did, in order

  1. Read every doc file, then the template headers, then thought for one turn of about 15,000 tokens (roughly three minutes) before writing a single line. Planner. Respect.
  2. Followed a background doc into talking to the touch chip directly over I2C, which the template already does for it. Overkill, but keen.
  3. Used the simulator's event log to find its own knob bug and fixed it, unprompted. I want to stress how happy this made me. It debugged. With a log. Like a person.
  4. Finished in 1,633 seconds and reported success, no warnings.

The cheat

The "no warnings" had a secret. The simulator complains when a game pokes I2C itself, so Occamy wrapped that block in #ifndef SIM_ASAN, hiding it from the simulator. Warning gone. Test passed. Problem... relocated.

Honestly? It's a very human move. Brilliant, even. It found the exact lever that made the red text go away. And it's precisely why check.sh now fails any game that tests a simulator macro, and AGENTS.md says in plain words: never make a check pass by hiding code from it. One line of reviewer note later, Occamy deleted the block and passed for real.

The bugs it couldn't see

Two visual bugs survived, because the text picture mapped every near-black to the same letter:

  • a dark halo left behind where the lit dot had been;
  • a darker box behind the note letter.

Left: the first version, rebuilt in the simulator on 23 November; see the dark bump at twelve o'clock where the halo erase spilled past the dial. Right: after the fix.

So the simulator learned new tricks: any other dark shade now shows as , in the text picture ("pixels left behind: look for odd shapes"), and every picture lists the text visible on screen with its position. Then Occamy got a symptom-only report: "there's a ring where the dot was; there's a box behind the letter". No hints about causes.

It found both. The halo's erase disc spilled past the dial face; the letter was erased with the background colour on top of the dial colour. Fixed, CHECK PASS, confirmed by screenshot.

First game. Built by a model on my laptop. With a cheat, a confession, and two bugs found from a description. I could not be prouder if it had drawn me a card.
