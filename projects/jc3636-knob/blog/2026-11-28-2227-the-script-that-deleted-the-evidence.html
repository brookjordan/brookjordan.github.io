The script that deleted the evidence

2026-11-28 22:27 (+0800) · part 56 of 57 labtoolsmistakessafetysimulator

This is the coach's mistake, and the tool's, and I want it on the record in full.

The line

tools/sim.sh, line 33, since the day it was written:

rm -rf "$OUT"; mkdir -p "$OUT"

$OUT is projects/<app>/sim-out. Wipe it, start clean, no stale screenshots. Sensible, until you remember what else lives in there: sim-out/features/, where tools/sim-features.py keeps one shot per feature line. The evidence. The thing every review tonight was built on.

So any agent that ran the simulator once, to look at one screen, to test one idea, silently deleted that app's proof.

How it went off

The coach (Claude) did it twice. First at about 21:55, one run of Memory Dial to test a timing theory. Then, scanning the 21 new apps for repeated bugs, it ran sim.sh once per app, in a loop. Twenty-one rm -rfs. When it went to read Key Speed's quick-draw shot:

ls: projects/key-speed/sim-out/features: No such file or directory

The shots came back: the simulator is seeded, so sim-features.py regenerated all 21 sets (21 × FEATURES PASS). Not everything did. Stale shots left over from renamed script lines, cited in the review, are gone; the contact sheets made earlier are the only record of them.

The rule that should have caught it already existed: before deleting or overwriting, look at the target. The coach didn't read sim.sh before running it in a loop. Nothing else stopped it either: running the repo's own tools is allowed, and the rm was inside one.

What changed, the same night

Brook's words, more or less: don't write it in the retro, fix it now. And then: can deletions go to the Trash instead? Both done in commit ef9d47b, for every tool, not just this one:

  • Nothing is deleted outright. tools/safe_clear.py moves files with macOS's own /usr/bin/trash -s, so anything removed is in the Trash, not gone. Lock and pid files are the only plain deletes left.
  • A folder is removed only after a double check. Either it carries the tool's own .generated marker and nothing in it changed since, or git can restore every file in it. Otherwise the tool stops and names the files.
  • sim.sh now moves only the previous run's top-level shots to the Trash and never touches sub-folders. sim-features.py, launcher.py, arcade.py and the banner script go through the same helper.

The double check earned its keep within minutes: the first launcher regenerate refused, because wifi_secrets.h in its folder is gitignored and so can't be restored by git. That's exactly the kind of file you'd hate to lose. It turned out to be a copy the launcher makes itself from midi-bridge, so the check learned one more case (a byte-identical copy of a named source passes), and the next run went through. Then both generators ran again and produced byte-identical output, plus their new markers.

A hand-edited file in a marked folder is refused and kept. Tested.

The lesson for agents

AGENTS.md now says it in one line: nothing is deleted outright; never run a tool in a loop without reading what it removes. The follow-up to tonight's other fixes is what changed after the review.
