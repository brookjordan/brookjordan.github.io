A folder for a flight

2026-11-19 18:41 (the laptop was on Pacific time) · part 6 of 26 labofflinetemplate

I had a flight coming up and a slightly unhinged idea: what if a model running entirely on my laptop, no internet at all, could make little games for the knob while I sat on a plane eating a bread roll? For that to work, everything it could possibly need had to be in one folder. So: one folder.

The lab root

At 18:41 the first commit landed: one folder, jc3636-knob. In it:

  • an AGENTS.md as the front door;
  • projects/, one folder per firmware (the usage panel, the vendor's own demo, and soon, games);
  • docs/: the vendor pack, the datasheets, and the documentation repos, cloned;
  • toolchain/: ESP-IDF 5.5.2, so a build never has to download anything.

Seven minutes later the docs were split into small docs/kb/ files, because a local model has a much smaller attention span than the cloud ones, and a 40-page "everything about the board" document is a great way to make it forget what it was doing halfway down page two.

The template, and the number

At 18:54: projects/game-template. Every game starts as a copy of it. It drives the screen by writing straight into a framebuffer and sending only the rectangles that changed, with no graphics library in the way. Knob, touch, haptics and a little synthesiser for sound, all wrapped so a game never talks to a chip directly.

And on the board it ran at 63 frames a second. Sixty. Three. On a round screen over a four-wire bus, from a template written that evening. I'm aware that 63 fps is not news in the year of our lord 2026. I am choosing to be extremely excited anyway.

The demo game is "rim pong": the knob moves a paddle around the edge of the circle, a ball bounces around inside, and you try to keep it in.

Things the first afternoon decided

A few decisions from that evening are still load-bearing:

  • Sound starts muted. BOOT cycles mute → headphones → speaker and headphones, with a little dot at the top of the screen saying which (red, blue, green). That choice comes back to bite, delightfully, on 23 November.
  • The screen was rotated 180° in software, because the vendor demo mirrored it. That one also comes back to bite. Hard.
  • Starting a game is one command: tools/new-game.sh <name> copies the template and renames it. Not "copy these six folders and edit this CMake file". One command. A model can't get one command wrong. (Narrator: it can get almost anything wrong. But it couldn't get this wrong.)

What it didn't have yet

A way for the model to see what it drew. With no board plugged in on a plane, a game it wrote would compile and then... nothing. You'd find out at the gate whether anything worked.

That gap gets filled on the 21st, by a simulator, and it changes everything.
