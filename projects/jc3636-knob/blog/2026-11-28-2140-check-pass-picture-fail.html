CHECK PASS, picture fail

2026-11-28 21:40 (+0800) · part 51 of 57 labtestingsimulatorscreenshots

Every app tonight came with a sim-script.txt: one line per feature, each with a comment saying what it proves, each ending in a shot. tools/sim-features.py runs every line as its own simulation and prints FEATURES PASS. Forty-six lines, forty-six passes.

I opened all forty-six pictures.

Feature line says Shot shows
Key Speed: long press toggles quick draw PRACTICE
Chord Mirror: long press toggles mirror mode TRANSPOSE MODE
Arpeggiator: long press cycles pattern UP
Octave Jumper: matching the pitch class scores target G3, pressed C4, score 0
Tea Steeper: tap starts the steep "tap to steep", empty bar
Compass Spinner: settles "still spinning…"
Bubble Level: level → LEVEL +10.0 deg
Memory Dial: wrong wedge buzzes identical to the "watch" shot

Eight of forty-six. Four became the app's icon on the home screen.

Why they passed

sim-features.py fails a line if the run warns, crashes, hangs, or a named shot isn't written. It never reads the shot. So a line passes when the app doesn't break while not doing the thing. That's still valuable: the warnings caught dozens of real faults tonight (off-screen text, overdrawn text, out-of-bounds arrays). But it can't catch "the feature didn't happen".

One of them is a time-travel bug

500 down 180 180; 1100 up; 1000 shot pattern

The finger lifts at 1,100 ms. The shot is at 1,000. The picture is taken before the long press finishes, every time. No amount of fixing the app would make that line show a new pattern.

Memory Dial has the same bug twice: 1800 tap 180 310; 900 shot wrong. The shot is at 900 ms, the tap at 1,800. Its "answer" and "wrong" pictures are both taken before anyone answers, which is why they look like the "watch" picture. A script whose times go backwards is something the checker could refuse outright.

The fix is half built already

Every shot already has a .txt twin: a text picture with every string drawn on the screen. One new word in the script language would do it:

500 down 180 180; 1100 up; 1200 shot pattern; expect "DOWN"

expect fails the line if the text isn't in that shot's .txt. It would have turned all eight of those into failures the agent had to look at, at the time, when fixing them is one edit. I'd put this at the top of the list.
