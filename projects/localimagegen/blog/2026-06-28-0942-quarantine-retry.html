Pardoning the quarantine: lig retry

2026-06-28 09:42 · feature resilience failures cli

The quarantine system works. A cell that fails MAX_ATTEMPTS times is locked out so a broken model or a bad scene doesn't loop forever burning GPU time. That's the point.

But transient failures exist. ComfyUI hiccups, a timeout fires at the wrong moment, chroma's first attempt hits a memory spike. The cell gets three strikes — legitimately — and then it's permanently benched. The only escape was editing config/failures.json by hand and deleting the entry. That wipes the audit trail: you lose when it failed, why it was locked, and how many times it tried.

That's the problem lig retry solves.

The design: floor, not erasure

The failure record gains a floor field — an integer discount applied before the quarantine cap is checked. computeWork in src/reconcile.ts now uses effectiveAttempts = attempts - (floor ?? 0) when deciding whether a cell is quarantined. If you've made three attempts and the cap is three, you're out. If someone sets floor = 3, your effective count drops to zero — you get a fresh chance.

retryFailures() in src/config.ts advances floor to attempts, which is exactly that. The history is preserved: all three original failure timestamps and reasons are still in the record. What changed is the discount that lets the cell back into the queue.

Think of it as a pardon, not an expungement. The record stays; the lock is lifted.

A retriedAt timestamp is written alongside floor so there's an audit trail on the retry itself: when did we decide to give this cell another chance?

The command

lig retry                   # retry all quarantined cells
lig retry --model chroma    # only chroma cells
lig retry --reason "not produced"  # only cells whose failure reason matches the pattern
lig retry --all             # alias for no filters

The flags compose: --model chroma --reason timeout retries only chroma cells that failed with "timeout" in the reason. The output lists exactly which cells were unblocked.

Why this matters

The immediate trigger was chroma: a batch of cells landed in quarantine with generic "not produced" reasons after a transient ComfyUI hiccup. The model is fine; the cells just need one more run. With lig retry --model chroma they're back in the queue without losing any history of what happened before.

More generally: the quarantine cap is the right default, but it should be overridable with surgical precision and a full audit trail. This makes it so.
