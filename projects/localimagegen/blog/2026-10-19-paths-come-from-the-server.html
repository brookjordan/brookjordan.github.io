The paths come from the server now

2026-10-19 23:45 · incident lesson tooling

Brook, at some ungodly hour, staring at a run that had just "finished": 96 images rendered, zero images saved. No error. No warning. Not so much as a raised eyebrow from the machine. And then, the same afternoon, lig doctor cheerfully reported that 0 of 32 models were installed, on a machine with 150 GB of models installed. The computer was not lying. It was answering a question nobody meant to ask.

Both failures were one stale path. One. Wrong. String.

Two crimes, one culprit

ComfyUI moved house on 2026-10-15, from ~/ComfyUI-Installs + ~/ComfyUI-Shared to ~/Documents/Comfy_Installs/ComfyUI + ~/Documents/ComfyUI-Shared. config/gallery.ts still described the old world, because it had not changed since the commit called "WIP snapshot before machine migration". A snapshot, frozen in amber, quietly running the country.

And here is the trap, and it is a beautiful trap: the old tree still exists. ~/ComfyUI-Shared/output/localimagegen is a real directory, empty, sitting exactly where the config pointed. Not a 404. Not a stack trace. An empty room with the lights on. Every check that looked in it found a directory, found it writable, found nothing wrong.

So:

  • Stamping found nothing. run builds a graph, ComfyUI writes the PNG into the live inbox, and stampItem looks for it under paths.comfy_output, the empty legacy directory. fs.existsSync says no, continue, and the render is dropped without a word. 96 times. Ninety. Six. Times.
  • doctor looked in the wrong tree. It derived the models root as <output>/../models, which is correct only if the output dir sits beside the shared tree. Pointed at the legacy root, it checked an empty directory and reported every model missing. The machine then spent a session re-downloading things the NAS already had. Half a re-fetch, all waste.

One wrong string, two failures that looked completely unrelated, like identical twins committing crimes in different postcodes.

The fix: ask the process that is writing the files

Hardcoding the new location would only move the bug to the next migration. We have been here before, and the whole lesson is that some other human will move this tree again, because that is what humans do to directories. The running server already knows its own layout: it advertises --base-directory and --output-directory in /system_stats. So the process writing the files is now the source of truth, and the config file has been demoted.

  • src/comfypaths.ts reads the argv, and loadConfig rebases comfy_output onto the server's real output directory. config/gallery.ts is now the offline fallback, not the authority. It gets a vote only when the server is not speaking.
  • scripts/lib/comfy-paths.zsh does the same for shell scripts, which resolve the tree from disk rather than trusting anyone's memory of it.
  • ~/.zshrc autodetects DIR_COMFY_INSTALL / DIR_COMFY_SHARED instead of naming the old location. It had been feeding wrong paths to comfy-start and to ~/.local/bin/comfy-profile, which was already correct. So the next time ComfyUI crashed and got relaunched, the relaunch would have failed while the profiler sat there smug.
  • yarn preflight compares config against the live server and exits non-zero on a mismatch. Tested the honest way: we put the old path back on purpose, and it failed, and it said why.

What we kept: the renders were not wasted

lig refresh-data stamped all 96 into masters/ once the inbox resolved. But reading the evidence afterwards nearly made the diagnosis wronger, and that deserves its own paragraph of shame:

  • Their mtimes look like the render time, hours earlier. importAsWebp deliberately copies the source PNG's mtime onto the WebP (src/stamp.ts), so a file written at 23:21 can claim 23:07. A correct diagnosis was nearly strangled by a timestamp with a fake alibi.
  • The run's own log said stamped 0 straggler(s). That counts only stragglers; the normal path is refreshData. So the log reads as success while moving nothing. A very confident green tick attached to zero work.

The second bug, smaller and sneakier

krea2 asked for krea2_turbo-Q8_0.gguf, where the upstream file krea2-turbo-Q8_0.gguf joins the halves the other way. One character, the entire family, failed forever, quietly. The fetch script now renames on purpose and says so in a comment, because future us deserves an explanation, not a mystery.

What still hurts

run should have noticed that it rendered 96 images and moved zero. That check does not exist yet; it is the obvious next one, and until it exists the absence of an error message remains what it has always been: not evidence that a step worked. A wrong absolute path is a silent failure, not a loud one, and silence in this codebase has a track record of lying through its teeth.
