Image notes: the gallery gets opinions

2026-06-26 14:36 · feature gallery notes routing

The gallery was a passive thing until today — a bake-off with no memory. You'd look at a krea2 doll render, think "wow, that face is uncanny," and then scroll on. Nothing wrote that down. Nothing remembered it.

That changes now.

What shipped (phase 1)

Click any image. A full-screen lightbox opens: the image fills the left, a focused textarea is on the right. Type. It saves automatically — 1 second after you stop typing, or immediately on Cmd/Ctrl+Enter or blur. Close with Esc, the backdrop, or the close button.

Notes are free text, no tags. That's intentional — let the corpus develop some natural vocabulary before imposing structure. Tags can come in phase 2 when we aggregate.

Once a slide has a note, it gets a small blue dot in the corner. Subtle but unmistakable. Open that image again and your note is waiting.

How it works

Storage is config/notes.json — a plain Record<cellKey, NoteRecord>, git-tracked, human-editable, machine-written. Same design philosophy as config/seeds.auto.json: the machine owns the file, you can hand-edit it, and it's committed so the corpus lives with the code.

// config/notes.json
{
  "krea2_doll_s08_02026": {
    "text": "great face structure, skin is a bit plasticky",
    "createdAt": "2026-06-26T06:35:14.199Z",
    "updatedAt": "2026-06-26T06:35:14.199Z"
  }
}

Write-path is lig serve --flexible only. The POST /api/notes endpoint is wired into the flexible server — the static Netlify page is read-only. That's intentional: the author experience is local, the audience experience is read-only. Notes committed to the repo then deploy with the next lig deploy.

The key is the existing cellKey(model, scene, sample, seed) from src/naming.ts — the same key data/meta.json already uses. No new ID scheme, no migration.

Baking: build/data/notes.json is emitted by writeData() (stamp.ts) on every data refresh, and baked into the offline static page as BAKED_NOTES alongside BAKED_META and BAKED_PROMPTS. The static site can show notes without a server.

What it replaces

Nothing — the gallery had no note concept before. This is net-new.

Why (the real reason)

There's a longer arc here. The plan is in .claude/plans/image_notes_and_routing_a5640991.plan.md:

  • Phase 1 (now): free-text notes, gallery editor, git-tracked corpus.
  • Phase 2 (later): aggregate into per-model strength/weakness profiles. Which models are "painterly"? Which are "plasticky"? Which reliably nail faces?
  • Phase 3 (eventual): a lig recommend <look> router — the engine consults the profiles and picks a local model. That includes the agent picking a model for blog banners without asking.

The bet: the most valuable thing we can do with a 1,000-image matrix isn't just render more images. It's to start attaching meaning to what we already have.

Phase 1 is the shovel. Now the digging starts.
