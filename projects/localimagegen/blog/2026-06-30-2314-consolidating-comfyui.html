One ComfyUI to rule them all (and the venv trap)

2026-06-30 · ops decision lesson

ComfyUI had sprawled across four places: ~/ComfyUI-Installs (a CLI clone), ~/ComfyUI-Shared (where Comfy's own auto-installer drops models), ~/Documents/ComfyUI (the Desktop app's user data), and the Comfy Desktop.app bundle itself. Models, custom nodes, and outputs were split between them. lig run/watch only care about one thing — a reachable ComfyUI that reads the right models and writes to the output we scan — so the scatter was pure friction.

Decision: ~/ComfyUI-Shared is the single source of truth

Everything now lives under ~/ComfyUI-Shared:

  • models/ (legacy clip/ → text_encoders/, unet/ → diffusion_models/ merged into the modern names), custom_nodes/, input/, output/, user/ (incl. comfyui.db and the output/localimagegen symlink the pipeline relies on), the ComfyUI/ source, and the .venv/.
  • The Desktop app was repointed at it (~/Library/Application Support/ComfyUI/config.json basePath + extra_models_config.yaml base_path), so its auto-installs land here too.
  • ~/Documents/ComfyUI and ~/ComfyUI-Installs were deleted.

Why ComfyUI-Shared over Documents: it's already where Comfy's auto-installer writes, it's outside iCloud-synced Documents, and the name says what it is. The only repo-side change is config/gallery.ts → comfy_output_base: '…/ComfyUI-Shared/output'.

Lesson 1 — ComfyUI Desktop has no CLI launcher

I assumed the Desktop app could double as the headless launcher. It can't: its server is bundled inside app.asar and it runs a private bootstrap-python — there's no main.py you can hand --listen, --reserve-vram, --port and friends. That's why a separate source clone exists. So lig run/watch need the ~/ComfyUI-Shared/ComfyUI clone, launched via the comfy-serve / comfy-listen aliases in ~/.zshrc (now all pathed through $DIR_COMFY_SHARED).

Lesson 2 — don't trust ComfyUI's unpinned requirements when rebuilding the venv

Deleting ComfyUI-Installs took the ComfyUI source with it, and the relocated venv's site-packages didn't survive either. Re-cloning + uv pip install -r requirements.txt rebuilt a working core — but ComfyUI pins its ML stack loosely (torch, transformers>=4.50.3), so uv pulled transformers 5.x + torch 2.12. That broke custom nodes (VibeVoice's config registration clashes on 5.x) and, worse, risked silently changing how the Qwen/Ovis text encoders behave — i.e. not reproducing the masters.

A saved ~/ComfyUI-Shared/venv-requirements.txt freeze of the working env had the proven versions (transformers==4.57.6, gguf==0.19.0, torch==2.10.0…). But a faithful full reinstall of that freeze is impossible: it's internally inconsistent (audio-separator==0.6.4 needs soundfile<0.12, yet the freeze also pins soundfile==0.13.1) and fairseq==0.12.2 won't build on Python 3.12. Both offenders are the audio/TTS stack — nothing the gallery touches.

So I did a focused restore instead of chasing the whole freeze:

  • transformers==4.57.6 (also pulled huggingface-hub back to 0.36.2, exactly the freeze), accelerate==1.13.0, gguf==0.19.0 — keeping the already-working torch 2.12.1 (MPS: True).
  • src/graphs.ts only uses core nodes + UnetLoaderGGUF and core SaveImage, so once ComfyUI-GGUF (krea2 / Flux GGUF) imported cleanly the gallery was unblocked. The other custom nodes (VibeVoice, Detail-Daemon, VideoHelperSuite, RES4LYF, Easy-Use, comfy-image-saver) were left broken for the moment — they don't affect renders — then restored next (Lesson 3).

Lesson 3 — slaying the beast of IMPORT FAILURES

And lo, six custom nodes lay broken in the dust, each howling its own IMPORT FAILED into the uncaring void. The gallery itself was safe — graphs.ts kneels only to the core and the mighty UnetLoaderGGUF — but the people cried out across the land: "I'll need them back still." So we girded our loins, raised the holy uv, and rode out to war.

The beast, in the end, was a paper dragon wearing a borrowed roar. Each node had fallen to one — one! — missing, wheel-installable package. No compiles from the forge. No fairseq (which will not build on Python 3.12 for love nor sacrifice). No audio-separator/soundfile blood-feud (the freeze's twin poisons — and glory be, nothing in this realm even wants them). We felled them in a single thunderous charge:

The fallen node The curse it bore The blade that freed it
ComfyUI-Easy-Use No module named 'lark' lark
comfy-image-saver No module named 'piexif' piexif
VideoHelperSuite No module named 'cv2' opencv-python
ComfyUI-Detail-Daemon No module named 'matplotlib' matplotlib
RES4LYF No module named 'pywt' PyWavelets
ComfyUI-VibeVoice No module named 'diffusers' diffusers

But the beast kept two heads in reserve, and they were sly:

  • Import-time vs runtime. VibeVoice rose the instant diffusers touched its brow — yet its own requirements.txt hid a second ambush for the hour of actual speech: librosa, soundfile, s3tokenizer, conformer, bitsandbytes. Summoning librosa unpinned hauled in a numpy-2-friendly numba, which nudged numpy 2.5.0 → 2.4.6 — a flesh wound; a clean re-boot swore nothing else had bled. And bitsandbytes==0.49.2, that fabled 8-bit troll said to haunt Apple Silicon? It had a macOS arm64 wheel all along and came quietly (it stirs only if you demand quantization).
  • The freeze is a menu, not a recipe. venv-requirements.txt won't reinstall wholesale, but it's the perfect reference for which version of each dep is known-good. Install what a node truly imports, pin from the freeze when it matters, and step around the audio-stack landmines you don't need.

When the dust settled and ComfyUI rose from the ashes, the tally read: 0 IMPORT FAILURES. The beast was slain; the nodes walk among us once more.

Takeaway for the next agent: ComfyUI lives at ~/ComfyUI-Shared; launch it with comfy-serve. If you ever rebuild that venv, don't accept ComfyUI's unpinned latest — restore the pins above (transformers 4.57.6 era) so renders stay reproducible. And when a custom node won't import, read its one-line error first — it's almost always one missing wheel, not something that needs building.
