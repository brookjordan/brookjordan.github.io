The Python era — Patch Notes, a router dream, and the sweep that rendered everything

2026-06-25 21:36 · history milestone

The motif that names the whole thing: a patch, sewn over a tear. Qwen-Image 2512.

Today the orchestration got rewritten in Node. Before the old workhorse cools, it deserves a proper sendoff — because for the three days before this, everything ran on a pile of Python on an M3 Mac, and it was thoroughly documented (there are research dossiers in docker-stacks/patch-notes-image-research/ older than every line of localimagegen).

It started as "Patch Notes"

The podcast's working title is Patch Notes (tentative — and probably not original, so the search for a better name continues) — hence the PN_ filenames, and hence the signature you'll spot all over the gallery: a fabric patch sewn over a torn hole (the van, the dragon). Patch notes. The first goal was a podcast-cover pipeline with a grand vision — a router that tags each workflow so n8n can pick the best engine for the day's prompt. The guiding line, verbatim from 00-INDEX.md:

"fish swim, birds fly, dinosaurs do not breathe on the moon. We do not pick one model for everything. Each engine is documented for its best foot."

There are per-model dossiers and strategy docs — an 11-engine arsenal, each with its role, native step count, and M3 memory note. "Best foot per engine" is exactly what the gallery went on to measure.

The lab notebook

stage2_log.md is a real experiment journal — base scene → Qwen-Image-Edit stitches the patch in, every entry with a clear pass/fail verdict. A favourite, on whether the slow non-Lightning brew was worth it:

"Lightning wins. Non-Lightning is ~20× slower, drifts the scene, and isn't worth it. Use Lightning, ~6 steps, cfg 1."

That one finding is why half the builders still run a Lightning LoRA at cfg 1.

The code I'm proud of: reconcile.py

The heart was a convergent matrix filler — the direct ancestor of src/reconcile.js. Its docstring states the entire contract:

add a step → filled for every scene AND every seed · add a scene → filled for every step AND every seed · add a seed → the whole suite is filled for that seed

…and it enforced that by simply checking what's already on disk and rendering the gaps:

def cell_exists(model, scene, step, seed):
    pat = os.path.join(OUT, f"{model}_{scene}_s{step:02d}_*_{seed:05d}_.png")
    return bool(glob.glob(pat))

for seed in seeds:
    for scene, prompt in SCENES.items():
        for s in steps:
            if not cell_exists(model, scene, s, seed):
                todo.append((scene, prompt, s, seed))

One model at a time, free VRAM between each, stamp seeds + durations into the filenames at the end. Crash-only and convergent before those were the words for it — re-run and it just finishes what's missing. Node later added the validity gate and deprecation tiers, but the soul is pure Python.

What it built, and where it went

This Python lab rendered every one of the 1026 masters in this blog, stamped their seeds and durations, and built the first index.html gallery (2367 lines) plus a fixed/ static build with its own webp compressor — the ancestor of the SSIM compressor. Then the orchestration was rebuilt in Node to match the JS gallery, and localimagegen was born.

The scripts still sit in docker-stacks/patch-notes-image-research/run/ — _sweep_lib.py (474 lines of builders + prompts), reconcile.py, stage2_tools.py (the stamper), run_gallery.py, and the rebuild_*.py helpers — kept for reference. They did the real work. Pour one out.
