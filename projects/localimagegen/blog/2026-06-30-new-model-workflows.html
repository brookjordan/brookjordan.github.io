Four new model workflows: Pony, Illustrious, Anima, PixArt-Sigma

2026-06-30 · models graphs workflow

Added workflows for four models that are viable on the M3 36GB MacBook but weren't in the gallery yet. The assessment process (history/2026-06-30-0945-the-capability-axes.md) ruled out HiDream-I1 (FP8-only on MPS, CUDA quant) and Hunyuan Image 3 (bitsandbytes CUDA dep). These four passed.

What was added

pony — Pony Diffusion V6 XL

SDXL fine-tune with two important differences from the existing sdxl/realvisxl/juggernaut builders:

  • CLIP skip 2 (CLIPSetLastLayer, stop_at_clip_layer: -2) — Pony was trained on Danbooru-tagged images with CLIP skip 2; without it the quality tag conditioning doesn't fire correctly.
  • Score-tag prefix — score_9, score_8_up, score_7_up, prepended to the positive prompt; score_6_up, score_5_up, score_4_up, to the negative. These are how Pony signals desired quality tier.

Uses the same SDXL Lightning 4-step/8-step LoRA split (ceiling 8, steps.add: [1]).

To make the prefix work with the JSON template, applyPrompt() in src/graphs.ts was changed from an equality check (=== '{{prompt}}') to an include+replace check (includes('{{prompt}}') → .replace()). This is backward-compatible and lets any builder embed a prefix or suffix around the placeholder. The pony positive template is literally "score_9, score_8_up, score_7_up, {{prompt}}" in the committed JSON.

src/workflows.ts (export path) and buildGraph (load path) were both updated to include pony alongside sdxl in the 4-step/8-step LoRA threshold check, so pony.t2i.high.json is generated and loaded correctly for steps > 4.

illustrious — Illustrious-XL v2.0

Config-only addition — uses the existing sdxl builder with a different checkpoint (illustriousXL_v2.safetensors). Illustrious v2 is eps-pred SDXL with anime/illustration emphasis; no CLIP skip or score tags needed, Lightning LoRA works as-is.

Deliberate decision not to add v3.5 VPred here: the V-prediction variant needs a ModelSamplingDiscrete node and can't use Lightning LoRA (mismatched training objective), which means 20-25 step runs — 3-4× slower than the rest of the gallery. Noted as future work if there's a V-pred-compatible distillation LoRA.

anima — Anima Base v1.0

Genuinely new architecture: Cosmos-based 2B BF16 diffusion model from CircleStone Labs / Comfy Org. New builder:

  • UNETLoader (anima-base-v1.0.safetensors → models/diffusion_models/)
  • CLIPLoader (qwen_3_06b_base.safetensors, type: qwen_image) — the anima type was tried and rejected; the model is Qwen-based internally so qwen_image is correct
  • VAELoader (qwen_image_vae.safetensors) — already present on disk; shared with qwen2512 and krea2
  • KSampler: euler / normal / CFG 4.0, ceiling 18, prompt_size: m

Standard ComfyUI sampler used (euler) rather than the community er_sde (which requires KJNodes) to avoid a custom-node dependency.

pixartsigma — PixArt-Sigma XL-2

Pre-FLUX DiT (0.6B) with T5-XXL text encoder. New builder:

  • PixArtCheckpointLoader (PixArt-Sigma-XL-2-1024-MS.pth, PixArtMS_Sigma_XL_2) — requires ComfyUI_ExtraModels (city96) — the only custom-node dependency in the gallery
  • CLIPLoader (t5xxl_fp8_e4m3fn.safetensors, type: pixart) — pixart is a built-in ComfyUI CLIPLoader type (added natively). Uses the same T5 fp8 file already present for chroma; it runs on CPU so FP8 is fine on MPS.
  • VAELoader (sdxl_vae.safetensors) — PixArt-Sigma requires a separate SDXL VAE; NOT bundled in the checkpoint. Users must download separately.
  • KSampler: dpmpp_2m / karras / CFG 4.5, ceiling 20, prompt_size: m
