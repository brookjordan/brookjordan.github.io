Incident — deploy was an overlay, not a mirror

2026-06-26 08:43 · incident ops lesson

Symptom: Python-era files kept turning up in the published site under projects/localimagegen/ — optimize_images.py, _manifest.json, build.py, build_static.py, and a stray __pycache__/optimize_images.cpython-312.pyc. Two of them (optimize_images.py, _manifest.json) were already tracked and live on brook.dev; the rest were one careless git add -A away from joining them.

Cause: deploy was deliberately non-destructive. It copied index.html + data/img/blog/flexible over the top of the destination and wrote .nojekyll, but it never removed anything. So whatever had ever landed in that folder stayed — including the entire pre-Node Python build system that used to live there. An additive deploy doesn't publish the build; it publishes the build plus every sediment layer underneath it. (The old behaviour even half-knew this: it only flagged leftover flat *.avif/*.webp as "safe to prune", and left them.)

Fix: make deploy a mirror (src/deploy.ts). The project folder is fully owned by this tool, so the destination must equal the build output:

  1. Copy exactly the artifacts a build produces — index.html, .nojekyll, and data/ img/ blog/ flexible/.
  2. Prune everything else at the destination top level (that's what swept out the five Python-era files).
  3. Drop each published dir before recopying, so images removed from the matrix also disappear downstream — a true mirror, not an overlay.

Two guard-rails so "authoritative" never means "foot-gun": it refuses to run on an empty/absent build (otherwise mirroring would wipe the live folder), and it leaves a nested .git untouched.

Lesson: a publish step that only adds is a publish step that accumulates. The whole of localimagegen already runs on "desired state in, actual state reconciled, no orphans" — deploy was the one step that didn't, and it quietly leaked years-old tooling onto the public site. Make the last mile obey the same rule as the rest: destination ≡ build, nothing more. Run yarn deploy; it now prints what it pruned.
