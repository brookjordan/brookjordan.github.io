Incident: the repair sweep that out-measured the sweep

2026-07-01 15:35 · incident lesson tooling

yarn mem:sweep measured every model three times — 54 measurements — then announced a repair sweep of 66 more. More repairs than originals. The sweep meant to clean up the data was about to do twice the work of collecting it, and, worse, learn nothing.

What happened

The sweep flags a model for re-measurement when one of its three footprints is an "outlier" (>max(1.5 GB, 15%) from the model's median). The old repair plan then re-measured each flagged model REPAIR_REPEATS = 3 times, and ran one filler model before each repeat to avoid carry-over — so 6 measurements per flagged model.

11 of 18 models tripped the outlier check. 11 × 6 = 66. The arithmetic was working perfectly; the premise was wrong.

Root cause

Two layers, one real.

The surface bug: interleaving a filler per repeat multiplied the cost, and nothing capped the total, so a noisy run ballooned instead of degrading gracefully.

The real cause: the threshold was tighter than the machine's own noise. Footprint is baseline − trough (free RAM before the render minus the low-water mark during it). The baseline alone swung 9.3 GB (σ 2.4) across the run — 21.5 GB one restart, 30.8 GB the next. On Apple-Silicon unified memory there's no dedicated VRAM: "free" is whatever the OS hasn't handed to the page cache or other apps. Reading a different multi-GB model each restart churns that cache, so how much reclaimable memory is lying around — and therefore how far free drops when the model loads — varies by run. Three clean readings of krea2 were 19.3 / 22.7 / 16.2 GB; of sdxlbase, 8.3 / 18.2 / 14.1. That's the environment, not the model. Re-measuring environmental noise doesn't converge — the repair readings are just as noisy. It's a treadmill.

The fix

Three changes (src/mem-sweep.ts, surfaced via lig mem …, orchestrated by scripts/mem-sweep.zsh):

  1. Median, not "drop outliers then mean." aggregate now takes the median of each model's readings. A single wild reading can't drag it, so the whole outlier-dropping heuristic — a worse reinvention of the median — is gone. krea2's 16.2 stays the answer whether or not a 22.7 shows up beside it.
  2. diagnoseStability names the failure. It separates the two modes, because they need opposite responses: environment (baseline volatile → fix the machine; re-measuring won't help) vs measurement (baseline steady but a footprint wobbles → a repair can average it out). The sweep prints the verdict in red at the top of every round once detected — and baseline volatility shows up as early as round 1.
  3. Bounded, gated repair. buildRepairPlan returns nothing unless the baseline is steady and only a handful of models are flagged. When it does run, it repeats each flagged model REPAIR_REPEATS times and pads the pool to ≥3 distinct models purely to interleave — no per-repeat multiplier. A circuit breaker skips repair entirely when more than a third of models are flagged (that's a noisy run, not a set of glitches). The repair can now never dwarf the main sweep.

On the run that started this, the new code returns an empty repair plan and a red "the machine is NOT quiet" warning instead of grinding 66 measurements.

Lessons

  • When your metric is a delta off a noisy baseline, fix the baseline — don't re-measure the noise. Quiet the machine (quit Electron apps and browsers, pause Spotlight / Time Machine / iCloud, drop Wi-Fi, sudo purge the page cache) and the footprints settle. No amount of re-running does that for you. The sweep now prints a read-only quietness preflight every run, and mem:sweep --quiet reversibly does the safe parts — an interactive "which of these should I quit?" checkbox of running apps (memory hogs pre-checked, the terminal running the sweep never offered), sudo purge before each measurement, and Wi-Fi off (restored on exit) — via scripts/mem-quiet.zsh (mem:quiet apps runs just the picker). It asks before quitting anything and never force-quits — a graceful quit lets an app keep its unsaved work — and for the daemons a script can't stop (Spotlight, Time Machine, iCloud, Photos analysis) it prints the exact command or setting to stop each yourself. The one thing to never quit for you is the terminal it's running in, so that's filtered out by $TERM_PROGRAM.
  • A robust estimator beats an outlier-chasing pipeline. The median did for free what the drop-then-average code did badly.
  • Keep the detector sensitive, but make the response proportionate. 15% is still an outlier — we want to notice wobble. What changed is that noticing a lot of it now triggers a warning, not a treadmill.
