Incident — flux4b s10 blank regression (applyModelFixes not wired)

2026-06-30 20:48 · incident lesson flux4b

Symptom: Ten flux4b masters at s=10 were 82-byte pure-black WebPs — stddev 0.00, same signature as the original Jun 24 incident. ComfyUI reported execution: success for every one, and the log emitted:

RuntimeWarning: invalid value encountered in cast
  img = Image.fromarray(np.clip(i, 0, 255).astype(np.uint8))

Cause: The NaN-sigma fix (BasicScheduler at s=10) was written into graphs.ts as applyModelFixes() but never called from buildGraph(). Since buildGraph prefers workflows/flux4b.t2i.json (which hardcodes Flux2Scheduler) over the programmatic builder, every JSON-path render at 10 steps sent the bad scheduler. The programmatic builder's branch was dead code from the moment the JSON file existed.

The function was defined; the call site was missing.

Affected cells (10 total, across two incidents):

Rendered Cells Seeds
Jun 26 embrace/kingdom/spirit/van × s10 1670940986 only
Jun 30 signage/instructions × s10 all 3

Jun 25 renders (doll/dragon seeds 42+2026, etc.) were already on disk from before the JSON path was introduced, so they used the programmatic builder and rendered correctly.

Fix: one line in buildGraph (src/graphs.ts):

applyModelFixes(graph, model, sample);   // ← this was missing

Called after applySeed, before returning the graph from the JSON path. applyModelFixes swaps Flux2Scheduler → BasicScheduler for flux4b at sample === 10, matching what the programmatic builder has done since Jun 24.

Recovery: deprecated the 10 cells via lig deprecate (6 selectors — by scene for the all-seeds cases, with seed=1670940986 for the partial cases). The 4 git-tracked blank files (Jun 26 batch) were restored first so they stay on disk until overwritten by a valid render. The 6 Jun 30 files were untracked and are gone; they land in the missing tier. lig run will re-render them in the next pass.

Lesson: defining a function and calling it are two different things. When a fix has two layers (the function, and the call site), both need tests or at minimum a smoke-check (buildGraph({ ..., sample: 10 }) → assert BasicScheduler). The programmatic builder and the JSON path now behave identically; applyModelFixes is the single place to update if another per-model quirk emerges.
