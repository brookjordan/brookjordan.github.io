The robot learns to phone home

2026-06-26 12:35 · architecture ops

The overnight shift ended with the autopilot "basically filing a bug report on itself" — catching its own infinite loop and quarantining the cells that wouldn't render. Cute. But that bug report went into a log I had to go read. The next chapter fixes two things at once: the robot should tell me when it trips, and it should never let failures pile up silently.

Every failure gets a bounded response

The guiding rule of the resilience plan: nothing blocks the loop, and nothing keeps grinding where it could quietly clog. So every failure class gets a bounded reaction:

  • Transient (ComfyUI unreachable, a flaky queue read) → retry with backoff.
  • Per-cell (blank, black, one cell errors) → the 3-strike quarantine we already shipped. Tried thrice, logged with the exact reason, set aside.
  • Per-model systemic → the new star (below).
  • Host-level (Comfy down past N, repeated stalls, disk full) → pause and back off, never crash, and ping when it recovers.

The loop always either makes progress or pauses cleanly. No more dog-chasing-tail.

The anti-pileup guard

The per-model tier is the one I'm most pleased with. If a checkpoint is missing or a model OOMs, every cell of that model throws the same error. The old behaviour would burn 3 × N doomed attempts grinding the whole model into quarantine one cell at a time. Instead: spot the repeated identical error class within a pass, skip the entire model for that pass, and fire one notification. One alert, not forty.

Knowing what actually broke

Right now we're forensic detectives working from the corpse — we inspect the output image (blank? black? wrong size?) and infer. But ComfyUI knows exactly what happened; we just never ask. The plan parses /history for execution_error entries — the failing node, the real exception — and maps the prompt_id back to its cell via the SaveImage prefix we already decode in src/stamp.ts. So "blank (stddev 0.7)" becomes "OOM on UNETLoader". That's the difference between "something's wrong" and "your fp8 weights don't load on MPS again" (see: krea2 on Apple Silicon).

The phone line

There's a pleasing full-circle here: this whole project started as an n8n podcast pipeline, and n8n is exactly how the robot will phone home. A new src/notify.ts POSTs a JSON event to a webhook; n8n routes it to Telegram. The cadence is deliberately smart, because a notifier that cries wolf gets muted by week two:

  • Immediate for host-level stuff (Comfy down, stall fired, disk error) + a recovery ping.
  • Batched digest for per-cell quarantines — collected, sent once per loop, not one buzz per dead pixel-soup.
  • Summaries for the satisfying beats: a sweep going clean, a fresh seed starting.

It's throttled and de-duped (one alert while a condition persists, one "all clear" after), and — crucially — wrapped in try/catch. A dead webhook must never break a render. The notifier is a passenger, never the driver.

The paper trail

Underneath the buzzing: an append-only logs/events.ndjson, one stamped JSON object per event, plus per-run provenance (git sha + the ComfyUI version from /system_stats) so six months from now I can tell which build and which Comfy produced a given mess. And the stall-timeout the overnight loop sorely wanted — waitDrain currently logs "no progress" into the void forever — finally gets teeth: time out, interrupt, free, skip-and-log.

A robot that works all night is great. A robot that works all night, texts you the moment it genuinely trips, and otherwise keeps its mouth shut? That's the one you actually trust to run unattended. 🦕
