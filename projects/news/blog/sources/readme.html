PodCast Builder — Project Map

Destination

A dependable local PodCast Builder produces complete daily episodes, stores durable media on the NAS HDD, publishes lightweight pages, and retains a recoverable operational record across generation, publication, and legacy migration.

Notes

Tracker: obsidian-project-tracking. This map records the production pipeline and its publishing/storage lifecycle. It is distinct from the Video Continuity benchmark project board, which owns motion-model comparisons.

This map was reconstructed on 2026-08-17 from current workflow evidence and the ongoing implementation conversation. Earlier activity is recorded only where supported by that evidence.

The PodCast Builder draft now draws from a curated source palette: independent British reporting (Novara Media and The Bristol Cable); Catanduanes-specific reporting plus a seven-day Catanduanes discovery feed; Singapore reporting (The Straits Times and Mothership); and frontend development updates (This Week in React and Smashing Magazine). The n8n workflow owns the exact feed URLs and priorities.

Decisions so far

  • the decision on public podcast asset storage: keep durable media on /volume2, serve it from assets.brook.dev, and leave only lightweight page metadata in GitHub.
  • PCB-007: add a deterministic startup capability manifest so the workflow can distinguish local, NAS, and per-endpoint route availability before expensive generation. Route preference is wired Ethernet, then wireless LAN, then Tailscale; the handoff's original ordering (Tailscale before WAN) was superseded, and "WAN" in the old config meant the wireless LAN at 192.168.0.25.

Not yet specified

  • The durable publication mechanism for small GitHub Pages metadata once NAS asset storage is live.
  • The pace and selection criteria for migrating legacy episodes after one full end-to-end rollout succeeds.

Out of scope

  • Rewriting Git history to reclaim historic media blobs. Removing live copies makes future deployments lighter, but history rewriting is a separate disruptive decision.
  • Motion-model benchmarking, which remains with the Video Continuity benchmark project board.

Run-time endpoint discovery added 2026-09-17. The manifest no longer uses hard-coded addresses alone. A new first node, Discover MacBook endpoints, runs ~/.local/bin/macbook-endpoints over SSH on the MacBook before ComfyUI starts. It reports the machine's real interfaces (classified by hardware port, so Ethernet is never guessed), its Tailscale address, the model-store mount state, and whether the LTX model set exists locally; it can also mount the NAS share itself when it is missing. The manifest builds its Ethernet → WLAN → Tailscale candidates from that report, keeping the old literals only as a fallback, and the LTX capability gate now names where the models were looked for instead of blaming the network.

NAS outage 2026-09-17, run 2567 lost. The NAS went offline mid-run. Tailscale last saw it at 05:18:11Z, two minutes after ComfyUI died. The sequence: the workflow had already switched to the ltx profile, ComfyUI had memory-mapped the 14.6 GB LTX text encoder from the SMB model store, the NAS dropped, the share vanished under the mapping, and Python died with SIGBUS (status=138) rather than erroring. The macOS shares (docker, model-store) disconnected at the same moment. Nothing on the MacBook was damaged; the stale ComfyUI lock left by run 2567 was released. Run 2567 had passed TTS (18 min), cover generation, the animation planner and the profile switch, so everything except the video model load is proven off-LAN.

Planned fix: local LTX models. The video stage pulls about 26 GB over the network mount, which costs roughly 24 minutes on the WAN path (measured 17.9 MB/s), loads the NAS heavily, and is the exact condition that produced the SIGBUS crash. the local vault/.local/bin/ltx-models-local copies the LTX model set from the NAS to ~/ComfyUI-Shared/models idempotently, with a --verify dry run. ComfyUI already prefers the local model directories, so no configuration change is needed. The MacBook has 156 GB free.

Local LTX model sync built 2026-09-17 — PCB-008. The earlier claim that "ComfyUI already prefers the local model directories, so no configuration change is needed" was unverified; it is now confirmed from the code (folder_paths.get_full_path returns the first os.path.isfile hit in insertion order, and extra_models_config.yaml declares local before nas_fallback) but still needs one empirical demonstration with the NAS unmounted. The replacement for the manual one-off copy is ltx-models-local.py, which syncs the four-file set (26.762 GB) detached and resumable, verifies each file against the content-addressed store (objects/sha256/<aa>/<digest> — the symlink target is the expected hash), and exposes a gate subcommand the workflow blocks on before the video stage. Staged in draft ee68b28b… as LLM config → Start LTX model sync → Fetch Repo Folders plus Get generated frame files → Gate LTX models local → Assert LTX models local → Start isolated LTX ComfyUI; the published version remains 65b620c7… until a run proves it. Also fixed while staging: Delete MP3s via SSH had been enabled by the cutover while referencing the removed MiniMax node Generate intro music, the only dangling reference in the workflow, so it threw after every successful publish; it is disabled again, matching the old builder.

Unattended SMB mounting is still unresolved. A mount on 2026-09-17 succeeded only after the user clicked an approval button, so the headless path remains unproven. A keychain entry exists for 100.84.158.31, and mount_smbfs without a password argument consults the login keychain, but the sandboxed agent process cannot exercise SMB syscalls, so the test has to come from a normal shell.

Note the n8n 2.x draft/published split, which caused confusion here: a manual run executes the editor's current draft, while a scheduled run executes the published version. Edits made through the API land in the draft (versionId) and do nothing for the schedule until the workflow is published (activeVersionId). Check both IDs match before trusting a scheduled run.

Open reminders

  • Tailscale DNS is only half-fixed. The NAS runs with tailscale set --accept-dns=false and MagicDNS still returns SERVFAIL for public names. The n8n containers no longer depend on it (the compose carries 1.1.1.1 as a fallback), but the clean end state is to set a tailnet global nameserver (Quad9 — 9.9.9.9, 149.112.112.112, Mullvad's own recommended replacement after retiring their public DNS) and then re-enable accept-dns.
  • N8N_API_KEY in /volume1/docker/n8n/.env is stale — n8n rejects it with 401. Harmless today because the MCP used here is n8n's native server, which does not use that key; regenerate it in n8n → Settings → API if anything else needs the public API.
    • Update 2026-09-17: the key has since been regenerated and now returns HTTP 200, so the public API is usable again for operations the MCP cannot perform (unarchive, publish, execution state).
  • N8N_MCP_TOKEN and OBSIDIAN_MCP_TOKEN were exposed in an agent transcript on 2026-09-16 and should be rotated.
  • Delete MP3s via SSH is dead code. It was enabled by the cutover while referencing the removed MiniMax node Generate intro music, so it threw after every successful publish. It is disabled again as of 2026-09-17. Its targets are .mp3 files that YuE2 no longer produces, so the open decision is whether to delete the node outright rather than leave it disabled.
  • NAS port 22 is filtered from the MacBook, so rsync-over-SSH to the NAS is not an option and SMB remains the only bulk transfer path.
  • Trim intro silence is disabled in both the old and new builders, so intro silence has never been trimmed. Decide whether to enable it.
