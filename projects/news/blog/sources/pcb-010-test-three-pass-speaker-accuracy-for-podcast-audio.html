Three-pass speaker test design

PCB-010 Test three-pass speaker accuracy for podcast audio

Objective

Make every generated speech segment prove that it says the intended line, uses the intended cloned voice, and is technically healthy before it enters the podcast. Generate at most three independent candidates per segment, accept the first candidate that clears all calibrated gates, and otherwise retain the best candidate with its evidence rather than silently choosing the last attempt.

This turns the original three-pass idea into a production selection policy that can be reused after PCB-009 changes the TTS engine.

Reuse rather than rebuild

Use the existing local systems:

  • Transcript check: use Parakeet TDT 0.6B v3 from the existing the local vault/git/brookjordan/localtranscription benchmark as the production first pass. Reuse the evaluation conventions in Transcription systems evaluation, including text normalisation and measured error rather than visual string equality.
  • Voice check: HEAR's local speaker-fingerprinting code and the selected CAM++ system from HEAR-010. Compare each candidate directly with the exact clean reference clip supplied to the TTS engine, not merely with a broad person gallery.
  • TTS: keep the generator behind an adapter so the selection loop works with the current engine and the eventual PCB-009 replacement.

Do not run VibeVoice-ASR in the podcast workflow. On this machine it is an 8.7B model with measured RTF around 2.18, and HEAR deliberately permits it to consume unusually high system resources for long-form transcription. The existing benchmark found Parakeet at RTF around 0.015 (about 67× realtime), 15/15 completion and a 95.0 corpus score, versus Qwen3-ASR 1.7B at RTF around 0.060 and a 96.1 corpus score. Short, single-speaker generated lines do not need VibeVoice's diarisation.

Use Parakeet for every candidate. Use Whisper large-v3-turbo as the initial bounded adjudicator only when Parakeet fails to decode, reports incomplete temporal coverage, or lands near a transcript threshold. Qwen3-ASR 1.7B remains the preferred measured-quality alternative, but its current .venv-asr import path is broken by an incompatible transformers / huggingface_hub combination; repairing and re-verifying it is optional follow-up, not a prerequisite for this ticket. Keep HEAR only for the lightweight CAM++ fingerprint pass. This reuses measured local systems without loading the destructive VibeVoice-ASR runtime or forking model logic into n8n Code nodes.

Per-candidate evidence

For each generated candidate, retain:

  • segment ID, attempt number, TTS engine/model/version, seed and generation parameters;
  • expected text, expected speaker and exact reference-audio hash;
  • output path, hash, codec, sample rate, channels and duration;
  • ASR transcript, token/word alignment where available, coverage and model version;
  • normalised WER, CER, missing-word count, added-word count and protected-term mismatches;
  • target-speaker similarity, strongest non-target similarity, speaker margin and fingerprinting system ID;
  • clipping, silence/drop-out, loudness, peak, DC-offset and duration-ratio measurements;
  • gate decisions, rejection reasons and final selection score/rank.

Write this as a machine-readable attempt manifest next to the audio. The final media manifest should point to the selected candidate and retain the rejected candidates until publication verification succeeds.

Health gates

A candidate passes only when every gate passes.

1. Technical audio gate

  • File decodes fully and has the expected sample format.
  • No NaN/invalid samples or truncated container.
  • Integrated loudness and true peak lie within the podcast's calibrated range.
  • Clipped-sample ratio, long-silence ratio and longest internal drop-out remain below measured limits.
  • Duration is plausible for the expected word count and does not contain a suspiciously long tail.

2. Transcript gate

Normalise both expected and observed text by Unicode form, case, punctuation, typographic apostrophes, whitespace and explicitly approved verbal equivalents. Preserve numbers, names and other protected terms.

Initial policy to validate:

  • preferred pass: normalised WER 0 and no protected-term mismatch;
  • provisional near-perfect pass: WER no greater than 0.02, CER no greater than 0.01, no missing content word, no added phrase and no protected-term mismatch;
  • ASR coverage must span the usable speech duration rather than returning a plausible partial sentence.

Punctuation and an expressive ellipsis are not spoken-word failures. A missing, repeated or hallucinated word is.

3. Voice gate

Embed the candidate and the exact TTS reference clips with HEAR's selected CAM++ system. Require:

  • the intended voice to be the top match;
  • target similarity above a calibrated floor;
  • margin over the strongest non-target voice above a calibrated floor;
  • no large drift between the first and second half of a longer segment.

Do not hard-code CAM++ scores from the two baseline clips as universal thresholds. Calibrate floors from known-good and deliberately wrong-voice examples after PCB-009 selects the production TTS engine. Store the system ID with every score because values are not portable between embedding models.

4. Perceptual-defect gate

Add measurements that complement ASR and identity:

  • repeated-word or repeated-phoneme detection from aligned ASR tokens;
  • unexpected long pauses inside a clause;
  • abrupt waveform discontinuities, bursts and drop-outs;
  • speaking-rate outliers against the expected text;
  • optional no-reference speech-quality score, accepted only after it separates known clean and defective samples.

Keep a small human-labelled calibration set of clean, wrong-word, wrong-voice, stuttered, clipped and pause-corrupted candidates. No automatic quality metric becomes a production gate until it improves classification on this set.

Three-attempt algorithm

For each script segment:

  1. Generate attempt 1 with an explicit seed and write its immutable evidence record.
  2. Run all four health gates.
  3. If it passes, select it immediately; do not spend two more generations merely because three are allowed.
  4. Otherwise generate a new candidate with a different seed. Feed rejection reasons into the next attempt only when the TTS adapter supports safe corrective controls; never rewrite the intended transcript.
  5. Repeat through attempt 3.
  6. If no attempt passes, choose the best fallback deterministically and mark the segment degraded.

Generate and validate segments independently so one bad line does not force regeneration of the whole episode. After selection, concatenate only the chosen candidates, then run a whole-episode check for ordering, missing/duplicated segments, speaker alternation, loudness consistency and final duration.

Fallback ranking after three failures

Use constrained lexicographic ranking rather than an uncalibrated weighted average:

  1. exclude undecodable, truncated or dangerously clipped files;
  2. prefer candidates whose intended speaker is the top fingerprint match;
  3. minimise protected-term errors, missing words, added words, then normalised WER/CER;
  4. maximise target-speaker margin, then target similarity;
  5. minimise perceptual-defect severity and loudness/duration deviations;
  6. break a complete tie by the lowest attempt number.

This makes transcript fidelity dominant without allowing a perfect transcript in the wrong voice to win. The manifest must say which gates failed and why the fallback won. Publication policy should initially require explicit review for any degraded segment; automatic publication of fallbacks is a separate decision after calibration evidence exists.

Workflow shape

Implement the loop as durable n8n state, not one long Code-node call:

  1. Prepare speech segment
  2. Generate candidate
  3. Persist candidate before evaluation
  4. Parakeet transcript evaluation
  5. HEAR voice-reference evaluation
  6. Audio signal health evaluation
  7. Collate candidate evidence
  8. Pass? → select, otherwise increment attempt
  9. Attempts remaining? → regenerate or rank fallback
  10. Persist selected segment
  11. after all segments: Assemble episode and Verify assembled episode

The persisted candidate path and manifest are the resume boundary. A retry must reuse completed candidates and evaluation records rather than synthesising them again unless an explicit regeneration flag is set.

Two reusable sub-workflows

1. Evaluate podcast speech candidate

A stateless, independently testable sub-workflow tagged subworkflow, podcast, and audio.

Typed JSON input:

  • candidatePath
  • expectedText
  • speakerId
  • referenceAudioPath
  • otherReferencePaths
  • segmentId
  • attempt

It calls a narrow local evaluator service on the Mac and returns:

  • technical: decode, duration, loudness, clipping, silence and discontinuity evidence;
  • transcript: Parakeet text, normalised WER/CER, additions, deletions, protected-term failures and temporal coverage;
  • adjudication: optional Whisper large-v3-turbo result and the reason it ran;
  • voice: CAM++ target score, strongest non-target score, margin, system ID and reference hashes;
  • defects: pause, repetition, rate and waveform-anomaly evidence;
  • passed, rejectionReasons, rankVector and evaluatorVersion.

The service should keep Parakeet and CAM++ workers warm and serialise inference. Whisper runs only for the bounded adjudication path. VibeVoice-ASR is absent from every process. n8n should orchestrate and persist results, not contain model code.

2. Generate and qualify podcast speech segment

A stateful sub-workflow called once per script item. Its typed input is the original segment plus mediaRunId, maxAttempts (fixed to 3 in production), voice-reference paths and evaluator endpoint.

Its state machine is:

Load existing segment manifest
  ├─ already selected and hashes still match → Return selected candidate
  └─ no valid selection
       → Generate attempt N
       → Persist candidate and generation metadata
       → Evaluate podcast speech candidate
       → Append immutable attempt evidence
       ├─ passed → mark selected → Return
       ├─ N < 3 → increment N → Generate attempt N
       └─ N = 3 → deterministic fallback ranking
                    → mark selected + degraded
                    → Return

Use a bounded explicit cycle inside this sub-workflow; do not run all three candidates eagerly. maxAttempts is a ceiling, not a batch size. Do not dispatch attempts concurrently because early acceptance should avoid generation cost and concurrent ComfyUI audio jobs would compete for the same machine.

The caller invokes this sub-workflow per segment with Execute Workflow in mode: each and waits for each result. The present workflow is sequential, so apparent fan-out does not provide concurrency anyway. Preserve segment order explicitly with segmentIndex and sort by it before episode assembly.

Persisted layout and idempotency

Use one stable directory per media run and segment:

<podcast staging>/<mediaRunId>/speech/<segmentIndex>/
  segment.json
  attempt-1.mp3
  attempt-1.evaluation.json
  attempt-2.mp3
  attempt-2.evaluation.json
  attempt-3.mp3
  attempt-3.evaluation.json
  selected.json

segment.json contains the expected-text hash, speaker ID, reference hashes, generator version and evaluator version. A retry may reuse an attempt only when these inputs still match. selected.json is written atomically and records whether selection passed or was degraded. Candidate filenames must not depend on $position; use stable segmentIndex and attempt so a retry cannot overwrite or reorder another line.

Before generating, read the manifest. After a client timeout, check whether the expected candidate and evaluation record landed before issuing another generation. This mirrors the production execution-retry guard: a lost response is not proof that work did not happen.

Selection policy in executable form

passed requires all of:

technical.safe
AND transcript.withinThreshold
AND transcript.coverageComplete
AND voice.targetIsTopMatch
AND voice.targetAboveFloor
AND voice.marginAboveFloor
AND defects.withinThreshold

After attempt 3, calculate rankVector as an ordered tuple rather than a blended score:

[
  technicalUsable,
  intendedVoiceIsTopMatch,
  -protectedTermFailures,
  -missingWords,
  -addedWords,
  -wer,
  voiceMargin,
  voiceTargetScore,
  -defectSeverity,
  -attempt
]

Compare tuple fields from left to right. This prevents a very strong voice score from compensating for missing speech and prevents a perfect transcript in the wrong voice from winning. Store both the tuple and human-readable explanation in selected.json.

Definition of done

Evaluator

  • A documented, versioned evaluator contract accepts one candidate plus expected text and voice references and returns the complete technical, transcript, voice, defect and ranking schema described above.
  • Parakeet and CAM++ stay warm in their own existing environments; the service serialises inference and a health endpoint reports each worker's readiness and model/system ID.
  • No evaluator process imports, loads or spawns VibeVoice-ASR. Process inspection during a full calibration run confirms this.
  • Transcript scoring uses Parakeet by default, bounded Whisper adjudication, normalised WER/CER, protected terms and temporal coverage.
  • Voice scoring uses HEAR CAM++ against the exact TTS reference and records target score, strongest non-target score, margin, reference hashes and system ID.
  • Technical and perceptual checks correctly reject the labelled wrong-word, omitted-phrase, repeated-phrase, wrong-voice, silence, clipping and truncation controls.
  • The complete v2026.39.5-22.57 speech set has a retained calibration report, measured resource use and human labels for the suspect and lowest-ranked controls.
  • Production thresholds are written back to this ticket with evidence; provisional HEAR defaults are not promoted merely because they already exist.

Selection and persistence

  • Every generated segment has one to three immutable candidate files and matching evaluation records under its stable mediaRunId/segmentIndex directory.
  • Attempt one is accepted immediately when it passes; attempts two and three are not generated unnecessarily.
  • Failed candidates are retained and never silently promoted as passes.
  • After three failures, the documented tuple comparison selects the same fallback from the same manifests on repeated runs and records a human-readable explanation.
  • selected.json distinguishes passed from degraded; initial production policy never publishes a degraded result automatically.
  • Changing expected text, speaker, reference hash, generator version or evaluator version invalidates stale selection state.

n8n integration

  • Both sub-workflows have typed contracts, descriptions and discovery tags and pass independent tests with pinned inputs.
  • The production caller returns every original segmentIndex exactly once, in order, with a selected file whose hash and manifest exist.
  • Whole-episode verification detects missing, duplicated or misordered segments and voice/loudness discontinuities.
  • A forced evaluator failure, synthesis timeout and n8n retry each resume from persisted state without duplicate synthesis or lost candidates.
  • A degraded segment stops before imaging/publication and produces one compact review notification with all three rejection summaries.
  • Workflow validation passes, connection read-back matches the intended graph, and a no-publish end-to-end execution completes.
  • One full shadow episode is reviewed against automatic decisions with no false accept before the gate is enabled.
  • The repaired workflow is published, its active version is recorded here, and one production execution reaches exact publication verification with no degraded segments.

PCB-022 evaluator-contract change v0.2.0 — 2026-09-28

Brook confirmed a real defect in the degraded-fallback selector, diagnosed against run 3092 segment 14 ("Verba Legis / Ratio Legis"): all three attempts failed, and the pipeline selected attempt 2 — by far the worst (WER 0.846, fluent nonsense) — over attempts 1 and 3 (WER 0.154 each).

Root cause, in localtranscription/scripts/speech_candidate_evaluator.py (build_rank_vector, contract v0.1.5): the rank vector compared missingWords/addedWords (positions 4–5) before WER, and those fields were raw length deltas — max(0, len diff) — not alignment-derived S/D/I. A same-length garble (0 missing, 1 added) therefore outranked a near-correct attempt that dropped one word. protectedTermFailures was unimplemented (None), and the perceptual-defect dimension was a 0.0 placeholder.

Fix, shipped as a versioned evaluator-contract change pcb-010-evaluator-v0.2.0 (commit 2e9e7d4 in localtranscription, per PCB-022's "no silent tweak" rule):

  • New _word_confusion: Levenshtein backtrace producing jiwer-compatible substitutions/deletions/insertions (Morris 2004 formulation); missingWords = S + D, addedWords = I.
  • Rank vector rebalanced: technical, voiceTop, -protectedTermFailures, -WER, -S, -D, -I, margin, targetScore, -defects, -attempt — WER promoted above the counts, so the headline transcript-closeness measure can no longer be outranked by a length artefact.
  • protected_terms implemented per episode: evaluate_candidate(..., protected_terms=[...]) counts protected terms absent from the observed transcript, recording both the count and the exact misses (protectedTermMisses); the bridge (pcb010_evaluator_api.py) accepts an optional protectedTerms list. Not yet passed by any workflow caller — wired but inert until the caller change.
