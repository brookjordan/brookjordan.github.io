Three-pass speaker test design

PCB-010 Test three-pass speaker accuracy for podcast audio

Question

Can a three-pass generation and verification loop reliably confirm that each podcast segment uses the requested speaker voice?

Design

For each test segment, generate audio with the requested voice, then run up to three verification attempts. Each attempt records the audio, transcript, detected speaker or similarity score, model and runtime details, seed, duration and failure reason.

The three passes should verify:

  1. audio is present, non-empty, decodable and free of obvious clipping;
  2. the spoken text matches the requested script closely enough for the acceptance threshold;
  3. the generated voice matches the requested speaker reference and is not merely intelligible speech from the wrong voice.

The retry workflow in the completed YuE2/LTX cutover ticket tested the retry behaviour with fixture transcripts. Replace those fixtures with generated audio and a speaker-verification method.

Acceptance criteria

  • Test the selected VibeVoice replacement and retain VibeVoice as a baseline.
  • Use authorised reference voices and a fixed, labelled corpus covering all podcast speakers.
  • Define thresholds before reviewing results, including transcription similarity and speaker similarity.
  • Produce a per-attempt result and a final passed or fallback decision for every segment.
  • Measure first-pass success, recovery rate, false acceptance, false rejection and runtime cost.
  • Do not connect the verifier to production publication until its output format and failure handling have been reviewed.
