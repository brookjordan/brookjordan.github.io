PCB-015 Retroactively build the podcast builder blog

Question

What does the Podcast Builder's history look like when told as a story — and can a deep dive through the vault's evidence produce the first posts of a builder blog in the same spirit as the local image gen project's blog?

Status

The blog exists and is live: 47 of 48 slots published at https://brook.dev/projects/news/blog/ (part of the site repo as projects/news/blog/). Only P05 remains held-evidence: it needs a real generated-image artefact plus a dated vision-inspection record in the vault before it can be written honestly. This ticket now owns the blog's ongoing maintenance: any agent updating the blog follows the maintenance protocol below.

Maintenance protocol (overview)

The blog is a maintained artifact. The full operating detail — file map, update cycle, add-a-post steps, gates, banner workflow, vault-hygiene rules — lives in the blog maintenance protocol packet and is mirrored in the build workspace README (the local vault/Documents/hermes/podcast-blog-preview-20260920/README.md).

Short version: when a ticket resolves or a failure accrues a real arc (decision → failure → fix), draft a new post from the vault evidence, run the build pipeline (node build.ts → verify.py → rsync into the site repo → commit/push → curl-verify). Cited vault notes are snapshotted publicly (sanitised) on every build, so keep must-stay-private material out of cited notes. The blog follows the records; it never anticipates them.
