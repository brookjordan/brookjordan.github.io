15 September environment and NAS preflight

2026-09-15 n8n environment and NAS preflight conversation

Source and purpose

Conversation evidence for PCB-007. Preserve the facts and the design request that led to the ticket; do not treat this packet as the current workflow state.

Verified topology

  • n8n runs on the NAS: 100.84.158.31.
  • ComfyUI and Ollama run on the MacBook: 100.98.203.89.
  • The podcast workflow must keep these roles separate:
    • serviceHost: NAS / n8n;
    • comfyHost: MacBook / ComfyUI;
    • llmHost: MacBook / Ollama.

NAS and SMB checks

  • Route selection must be checked per NAS address; smbutil view alone does not identify the transport.
  • On 2026-09-15, 10.10.10.2 and 192.168.0.224 routed via en0 (local/LAN), while 100.84.158.31 routed via utun4 (Tailscale).
  • TCP port 445 is reachable on the Tailscale address.
  • smbutil view //100.84.158.31 succeeds and lists model-store, model-cache, docker, and other NAS shares.
  • The preflight should try configured candidate addresses independently and record the selected interface, route class, latency/reachability, SMB discovery result, authentication state, and mount state.
  • No SMB share was mounted under /Volumes during the check.
  • /Volumes/model-store did not exist.
  • open smb://UG-NAS-X4800/model-store returned successfully, but did not produce a mounted share in the observed session.
  • A direct mount_smbfs attempt without credentials failed with an authentication error. No credential was entered into chat or stored in this packet.

ComfyUI model-path checks

The MacBook's ComfyUI configuration contains:

nas_fallback:
  base_path: /Volumes/model-store/models/comfyui

The active ComfyUI profile advertised several GGUF models but not the required:

LTX-2.5-Distilled-Q3_K_M.gguf

The local search path did not contain that exact filename. This does not prove the NAS copy is absent; it proves that the MacBook's current ComfyUI process was not advertising it and the expected NAS mount was not present.

Follow-up failure: YuE2 host-role miss

Execution 2524 failed at TEST — YuE2 synth with ECONNREFUSED 100.84.158.31:8087. The node was using serviceHost, which correctly identifies the NAS but is wrong for this MacBook-side media endpoint. It was corrected to use the configured MacBook llmHost on port 8087; the workflow read-back confirmed no remaining 8087 URL through serviceHost.

Design request captured

The workflow should discover, before expensive generation:

  • active Ethernet, Wi-Fi, and Tailscale paths;
  • usable routes to the MacBook, NAS, Ollama, and ComfyUI;
  • SMB share discovery, authentication, and mount status;
  • local and NAS model/custom-node availability;
  • the exact models registered by the active ComfyUI profile;
  • whether each required asset is local, NAS-backed, or unavailable.

It should create one capability manifest and fail early with checked locations and a precise cause. It should never silently substitute another model or profile. The LTX assertion must remain fail-closed.

Important distinction

A file existing on disk is not enough. The active ComfyUI profile must be able to see and register the file through its loader endpoint. The preflight therefore needs both filesystem checks and live ComfyUI capability checks.
