Blog maintenance protocol

2026-09-20 blog maintenance protocol

Operating detail for maintaining the PodCast Builder devlog. The ticket owns the overview; this packet owns the how-to. The build workspace's own README.md (the local vault/Documents/hermes/podcast-blog-preview-20260920/README.md) mirrors this content and is the copy most agents will read first.

Where things live

  • Build workspace (canonical build source): the local vault/Documents/hermes/podcast-blog-preview-20260920/
    • build.ts — the build. node build.ts from that directory. Reads senior-accepted drafts, renders posts + index, re-stages banner images, re-renders the sanitised sources/ snapshots. Uses marked/yaml from the localimagegen node_modules (no local install needed).
    • meta.ts — editorial layer: display title, blurb, topic per post ID. Edit titles and blurbs here, never in the drafts.
    • image-plan.ts — per-post banner: localimagegen master (scene, model rotation) → staged img/<id>-banner.webp.
    • citations.ts — per-post source list → public sources/*.html snapshot pages.
    • render-sources.py — renders cited vault/repo notes into sanitised public snapshots. Invoked by build.ts; can run alone.
    • verify.py — acceptance checks. Must be all-PASS after every build.
  • Drafts + dispositions (canonical post content): the local vault/Documents/hermes/podcast-blog-drafts-20260919/senior/ (accepted/*.md, dispositions.json). Only disposition: accepted-draft rows build.
  • Deployment target: site repo brookjordan.github.io, path projects/news/blog/. Deployment target only — never edit posts there.
  • Banner masters (read-only): the local vault/git/brookjordan/localimagegen/masters/ (recompressed 1280w q82 WebP via cwebp, cached in /tmp/blog-img).

Standard update cycle

  1. Edit the draft .md in senior/accepted/ (prose) and/or meta.ts (title/blurb/topic).
  2. node build.ts in the workspace — also re-renders sources/ snapshots from the vault, so vault edits flow through.
  3. python3 verify.py — all-PASS required (post count, held-slot exclusion, private-path leak scan for /Users/… and its citation links, link resolution, branding, clean tree).
  4. Deploy: rsync -a --delete preview/ <site-repo>/projects/news/blog/; in the site repo stage only projects/news/blog, commit, push. The site repo usually has unrelated dirty files; if master moved, stash → git pull --ff-only → pop → deploy.
  5. After the Pages/Netlify build, curl the changed URL(s) for HTTP 200.

Adding a new post

  1. Draft into senior/accepted/ as YYYY-MM-DD-p<NN>-<slug>.md: frontmatter (title, date, tags), a *Written retrospectively from records covering ….* preamble (the build parses the evidence window from it, then strips the line), ## What happened / ## What the evidence changed / ## Where we left it / ## Source notes sections, ≥2 source notes in the established obsidian-link style.
  2. Add the dispositions.json row with disposition: accepted-draft.
  3. Add meta.ts (topic, display title, blurb), image-plan.ts (banner master), citations.ts (source links) entries. New banners need a cwebp pass; see the build.ts image staging loop.
  4. Rebuild citations so any newly cited note gets a public snapshot, then node build.ts, verify.py, deploy per the standard cycle.

Part numbers ("Part N of 47") recompute automatically: oldest evidence window = Part 1. The featured post on the index is always the newest evidence window.

Gates a new post must pass (inherited from the drafting swarm)

  • 450–700 prose words (word floor enforced by the original intake gate; note it was applied inconsistently in the 2026-09-19 batch — 23 accepted drafts measure below it).
  • ≥2 source notes citing real vault/repo evidence; no invented timestamps or quotes.
  • Prescribed headings, no placeholders, no wikilinks, unslop checker exit 0.
  • Bounded wording: no claim the evidence does not grant.

Vault hygiene

Cited notes are snapshotted publicly on every build, sanitised (frontmatter stripped, wikilinks/obsidian links flattened, personal paths rewritten, internal plumbing mentions removed). Keep must-stay-private material out of cited notes, or in a separate uncited note. If a cited note becomes sensitive later, remove it from citations.ts and rebuild — the post just shows fewer sources.

New banners

Each post has a bespoke banner, rendered through the localimagegen engine and served from the assets share — not taken from the masters corpus and not committed to git. The full design and pipeline are in the bespoke banner render pass packet.

Short version: add an entry to render/render-plan.json (concept from the post's title/quip, scene family per the topic mapping — music/workflow→signage, incidents→dragon, cutover/migration→van, models/video→spirit, origins→kingdom — a model, a step count, and a cinematic prompt carrying the house patch motif), point image-plan.ts at https://assets.brook.dev/podcast/blog-banners/<id>-banner.webp, then run render/tools/run-detached.sh (resumable; --only <id> for one). Seed 42, 16:9 1280×720, cwebp -q 82 at 1280w. build.ts emits the URL with an onerror fallback to the gradient tile, so the image appears as soon as the render lands with no further deploy. Provenance is appended to render/provenance.jsonl.
