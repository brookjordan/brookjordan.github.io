House style and mechanics to copy

  • One dated Markdown file per post, with title, date and tags frontmatter.
  • Posts explain why a choice was made, what failed, what was rejected, and what the numbers showed. They are short, concrete and written as an engineering story rather than a white paper.
  • Incidents are especially useful for the podcast blog. They name the symptom, the misleading first theory, the evidence that changed the diagnosis, the fix, and the remaining uncertainty.
  • The blog build sorts entries and rewrites internal Markdown links. Do not use generated HTML as the primary evidence when the source Markdown exists.
  • CLAUDE.md says a blog post is expected for a notable feature, migration, decision, incident or lesson. That makes the history directory the best style reference for the podcast posts, not merely a visual example.

6. Working research recipes for later agents

To reconstruct one podcast incident

  1. Start at the relevant PCB ticket.
  2. Follow its evidence links into the podcast or LTX scratchpad.
  3. Find the n8n execution ID in the ticket or packet.
  4. Read the live workflow node graph before interpreting an execution, because node names and version state change.
  5. Fetch the execution with node data and record the failed node, input, output, exact error, timestamps, route manifest and any file names.
  6. Check the Daily note for what Brook observed or changed that day.
  7. Compare the result with the localimagegen incident style, then draft from the facts.

To reconstruct a date or timeline

  • Use the ticket's dated resolution first.
  • Use filename timestamps in scratchpad packets and n8n startedAt/stoppedAt values second.
  • Use Daily notes for context and user-visible sequence.
  • Use Git history and localimagegen frontmatter only for the house-style chronology or the image-generation origin story.
  • Never infer a precise event time from a note's modification time or from a generated build/blog file.

To collect raw numbers

Look for: execution IDs, startedAt/stoppedAt, node names, HTTP ports, route class, model names, file sizes, frame counts, clip durations, wall time, MPS held/refused memory, episode folder names, feed priorities, and Git commit hashes. Keep units and timezone in every extracted value.

  • Scratchpad evidence records historical state. The map and live n8n workflow own current state; do not promote old packet values without checking them.
