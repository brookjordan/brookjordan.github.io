PodCast Builder · devlog

16–19 Sep 2026

Written retrospectively from records covering 16 to 19 September 2026.

Style tags looked like a control panel. They were not one. In the local YuE2 runtime, the request's style and lyric text condition the render, but semantic classifier-free guidance was left at its default. The default cfg_scale is 1.0, which keeps a single branch and applies no guidance protocol. We had tags, and we had guidance as a documented experiment, but we had not enabled the latter.

What happened

The cutover record says the synth request leaves semantic guidance at its default. It also records that the CLI exposes no --cfg-scale flag, so enabling guidance requires the cfg_scale field in request JSON. The upstream documented experiment value was 1.2. That is a historical research value, not a promise that it improves a podcast.

The same record separates the style question from the lyric question. Style wording can name genre, instruments, vocal character and arrangement. Lyrics contain the words and supported section tags. A tag such as "strong lead vocal with restrained backing harmonies" is a conditioning request, not an assertion that the output will obey it.

What the evidence changed

The CFG evidence explains the mechanism. With cfg_scale at 1.0, the local runtime does not create a guided and unguided comparison branch. At 1.2, the protocol can pull generation towards the requested text, but the official guidance still says the value is not a guaranteed quality improvement. This is why we should not describe style tags as enabled guidance, or infer better vocals from the presence of a detailed prompt.

The budget is a separate axis. The semantic stage has a 9,000-frame ceiling, recorded as 360 seconds at 25 frames per second, while a song may emit its end token earlier. A ceiling is a safety bound, not a target. The output status and truncation flags also need separate inspection.

Where we left it

The captured podcast request remained unguided. The evidence supports a controlled future comparison that changes cfg_scale in request JSON and inspects truncation and listening results. It does not support changing production on the strength of the suggested value. Accent, backing-vocal prominence and similar qualities still lacked dedicated hard request fields and required listening judgement. The tags had a job; they just did not secretly become a mixing engineer.

That separation keeps the next experiment honest. One comparison can hold lyrics and style constant while changing the request field; another can test wording while leaving guidance untouched. Without that discipline, a nicer take would tell us only that several knobs moved at once, which is a very efficient way to learn nothing.

This is why the private record keeps the exact port, execution and branch relationship together. The prose can stay readable, while the ledger preserves the identity chain needed to distinguish a rerun from cached work. We would rather leave one boundary visible than smooth it over for the sake of a cleaner retrospective.
